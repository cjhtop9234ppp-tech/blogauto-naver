## 수정 시 지켜야 할 순서

1. 현재 실행 중인 사용자 런타임과 로그인 프로필을 건드리지 않습니다.
2. 관련 IPC와 preload API를 함께 확인합니다.
3. 일반 작업, 작업 이력, 회원마당 일일 작업을 분리해 회귀 영향을 확인합니다.
4. 단위 계약 검사와 JavaScript 문법 검사를 실행합니다.
5. 가능하면 별도 runtime/output에서 Electron smoke와 빌드를 수행합니다.
6. 실제 네이버 발행은 사용자 승인과 로그인 세션 확인 후 별도로 검증합니다.

## 특히 위험한 변경

- `naverPublisher.js`의 selector 변경
- `main.js`의 job ID·expected title 큐 변경
- `history.js`의 JSONL 재작성·중복 제거 변경
- `settings.js`의 runtime 경로 변경
- `codexRunner.js`의 timeout·재개 단계 변경
- 스케줄러 시간과 자동 종료 정책 변경

이 부분은 한 기능만 고치는 것처럼 보여도 로그인, 발행, 작업 이력, 재개 흐름에 동시에 영향을 줄 수 있습니다.
