# 오류 및 해결 이력

아래 표는 현재 소스와 README에서 확인되는 처리 경계와, 과거 로그에서 반복된 증상을 연결한 것입니다. 로그만으로 실제 원인을 확정할 수 없는 항목은 `확인 필요`로 표시합니다.

| 증상 | 확인된 원인/범위 | 확인 위치 | 대응 |
|---|---|---|---|
| 계정이 사라짐 | 실행파일별 userData/runtime 경로가 다를 수 있음 | `main.js`, `settings.js`, `accountStore.js` | 사용자 저장소 경로를 확인하고 같은 runtime 사용 |
| `agent-result.json` 없음 | Research 등 본문 생성 전 단계에서 중단 | 작업별 `jobs/job_<id>` | 원본이 있으면 재생성, 없으면 발행 불가 |
| 검색 후보 없음 | 주제의 현재성·공식성 요구에 비해 usable candidate 부족 | `search.js`, Research 로그 | 검색 보강 후에도 부족하면 확인 필요 보존 |
| 근거 부족 `REVISION/BLOCK` | 원문에 없는 법안번호·날짜·수치 또는 제목-본문 범위 불일치 | Main 검수 결과 | 임의 보완 금지, 원문·공식 출처 보강 |
| Image Worker 시간 초과 | Codex/Image 실행환경 또는 단일 작업 시간 제한 | `codexRunner.js` | 체크포인트·이미지별 progress 재사용, 실행환경 확인 |
| 태그 입력칸 없음 | Naver 편집기 DOM 변형 | `naverPublisher.js` | 태그는 선택 메타데이터로 처리하고 본문 발행과 분리 |
| 발행 버튼 클릭 timeout | 팝업/레이어가 pointer event를 가로챔 | `naverPublisher.js` | 팝업 확인·닫기 후 클릭, 실패 시 브라우저 유지 |
| 최종 발행 완료 확인 실패 | 첫 발행 버튼과 설정창 내부 최종 발행 버튼이 분리 | `naverPublisher.js` | 설정창·완료 신호·URL을 함께 확인 |
| 카테고리 찾지 못함 | 이력 카테고리명과 실제 Naver 카테고리 불일치 | `naverPublisher.js`, 이력 UI | 정확한 실제 카테고리만 사용, 잘못된 발행 중단 |
| 제목이 다른 초안 발행 | 다수 선택 처리에서 항목 식별이 불안정할 때 발생 가능 | `main.js` `publishHistoryDrafts` | job ID와 기대 제목을 함께 전달·검증 |
| 같은 글 반복 작성 | 선택 큐가 제목만 사용하거나 이전 editor를 재사용할 때 발생 가능 | `main.js`, `naverPublisher.js` | immutable `{jobId,title}` 큐와 새 페이지/대상 URL 사용 |
| 회원마당 링크 수집 실패 | 로그인 세션 또는 게시판 DOM/URL 구조 문제 | `memberBoardCrawler.js` | 로그인 대기·게시판 HTML 확인 |
| 글감 패널 닫기 실패 | Naver editor UI 변형 | `naverPublisher.js` | 출처 패널 오류를 본문 발행 실패로 확대하지 않음 |

## 오류 후 복구 원칙

1. 마지막 성공 체크포인트를 보존합니다.
2. 실패 단계와 원인을 `job-checkpoint.json` 및 복구 기록에 남깁니다.
3. 사용자가 오류 해결 프롬프트를 입력하면 해당 단계부터 재개합니다.
4. 완료된 Research/Writer/Image 결과를 재사용해야 하며, 재개 로그가 앞 단계 재실행을 보이면 복구 상태와 실제 실행파일 버전을 다시 확인해야 합니다.
5. 발행 오류 시 브라우저를 닫지 않고 사용자 확인 또는 재시도를 기다립니다.

## 오류 메시지 해석 원칙

`현재 작업 중입니다`는 실행 중이라는 뜻이며, `실패`, `확인 필요`, `재개 대기`는 다음 행동이 필요한 상태입니다. 단순히 마지막 로그가 오래됐다는 이유만으로 완료나 정지를 단정하지 않습니다.
