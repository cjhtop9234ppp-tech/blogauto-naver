# Blogauto Naver + Tistory

> [!IMPORTANT]
> **Naver 로그인 방식이 자동 로그인에서 수동 로그인으로 변경되었습니다.**
>
> 계정 보호를 위해 프로그램이 Naver 아이디와 비밀번호를 자동으로 입력하거나 로그인 버튼을 누르지 않습니다. 이에 따라 계정 관리 화면의 **Naver ID 및 Password 입력 항목도 제거되었습니다.** 계정에는 블로그 주소의 `Blog ID`만 등록하고, 세션 확인 또는 발행 중 로그인·캡챠 화면이 열리면 사용자가 해당 Chrome 창에서 아이디와 비밀번호를 직접 입력해 로그인해야 합니다. 로그인 완료 후에는 전용 Chrome 프로필에 저장된 세션을 재사용합니다.

Codex 기반 Windows 데스크톱 자동화 콘솔입니다. Naver Blog 글 생성/발행을 기본 흐름으로 사용하고, Naver 발행이 성공하면 같은 제목, 본문, 이미지, 카테고리, 태그를 Tistory 블로그에도 이어서 발행할 수 있습니다.

## 주요 기능

- Naver 계정 여러 개와 계정별 카테고리 관리
- 카테고리별 키워드, 발행 목적, 검색 채널, 블로그 신뢰 설정 관리
- Research/Title Agent, Writer Agent, Main Review Agent, Image Worker 기반 글 생성
- 현재성/공식성/신뢰매체 근거 검증
- Naver 세션 확인, 수동 보안 확인 후 세션 재사용
- Tistory Kakao 로그인 세션 확인 및 재사용
- Naver 발행 성공 후 Tistory 동일 글 자동 발행
- Tistory-only 테스트 발행
- 공개, 비공개, 예약 발행 설정
- 제목 이미지와 본문 이미지 생성 및 업로드
- 태그 입력, 카테고리 매칭, 인용구 스타일 변환
- TXT, MD, PDF, DOCX, XLSX, XLS, CSV, PPTX 원본 업로드 기반 글 생성
- 여러 원본의 표/문서 구역 보존 및 값 충돌 미리보기 표시
- 온새카 회원마당 원본 수집과 9개 고정 분류별 일일 발행 계획
- 기존 Naver 블로그 게시글의 초기 스타일 규칙 추출
- 초안 생성 후 항목별 승인, 승인된 항목만 발행
- Windows 작업 스케줄러 기반 회원마당 일일 자동 실행(A안)

## 기본 흐름

1. 계정 표시명과 Naver `Blog ID`, 카테고리, 키워드, 발행 목적을 설정합니다.
2. 필요하면 세션 일괄 확인으로 Naver와 Tistory 로그인 상태를 확인하고, 로그인 화면이 나오면 직접 로그인합니다.
3. Research/Title Agent가 주제와 제목 후보를 고르고 검색 근거를 수집합니다.
4. Writer Agent가 본문과 태그, 이미지 프롬프트를 작성합니다.
5. Main Review Agent가 제목 일치, 근거 신뢰도, 본문 품질, 독자 가치, 현재성 기준을 검토합니다.
6. Image Worker가 이미지를 생성합니다.
7. Naver Blog에 글을 작성하고 발행합니다.
8. Tistory 발행 옵션이 켜져 있고 세션이 유효하면 같은 글을 Tistory에도 발행합니다.

### 파일 업로드 기반 생성

작업 입력에서 `콘텐츠 생성 방식 → 파일 업로드`를 선택한 뒤 원본 파일을 여러 개 선택하거나 드롭합니다. 프로그램은 원문과 표를 공통 자료 구조로 정규화하고, 업로드 자료만 근거로 Research/Title Agent와 Writer Agent를 실행합니다. 파일 모드에서는 웹 검색을 실행하지 않으며, 지원하지 않는 HWP·이미지 파일은 업로드 대상으로 처리하지 않습니다.

미리보기에는 생성 상태, 원본 파일명, 태그, 감지된 값 충돌이 표시됩니다. 기본값은 `DRY_RUN`이며, `생성 후 Naver 발행까지 진행`을 명시적으로 켠 경우에만 기존 Naver 발행 흐름이 실행됩니다.

### 회원마당 일일 발행 흐름

작업 입력 아래의 `회원마당 일일 발행` 영역에서 다음 순서로 실행합니다.

1. `회원마당 수집`을 누릅니다. 열린 Chrome에서 회원마당 로그인이 필요하면 사용자가 직접 로그인·보안확인을 완료합니다.
2. 프로그램이 수집한 원본을 `member-board-source.json`에 저장하고, 정부·공공기관부터 일반 시사까지 9개 슬롯 계획을 만듭니다.
3. 필요하면 `기존 블로그 스타일 추출`을 한 번 실행합니다. 결과는 `naver-style-rules.json`에 저장되며 이후 초안 생성의 문체 참고자료로 사용됩니다.
4. `초안 생성`을 누르면 회원마당 원문을 최우선 사실 근거로 사용해 각 슬롯의 초안을 만듭니다. 이 단계에서는 발행하지 않습니다.
5. 초안별 `승인`을 누른 뒤 `승인 항목 발행`을 눌러야 네이버 발행이 진행됩니다. `소재없음`과 승인하지 않은 항목은 발행하지 않습니다.

일일 계획과 승인 상태는 `member-board-daily-plan.json`에 저장됩니다. 프로그램을 다시 시작하면 오늘 날짜의 저장된 계획을 자동으로 불러오며, `오늘 작업 불러오기` 버튼으로 수동 재로드할 수도 있습니다. 네이버 카테고리명은 계획의 9개 표시명과 실제 블로그 카테고리가 일치해야 하며, Chrome 로그인·CAPTCHA·보안확인은 자동 입력하지 않습니다. 수동 `승인 항목 발행`은 즉시 순차 발행하고, Windows 예약 실행의 12:00 발행은 승인된 항목을 슬롯 순서대로 10분 간격으로 발행합니다.

초안 생성 직후, 항목별 승인 직후, 발행 처리 직후에는 계획 파일을 즉시 갱신합니다. 이미 초안·승인·발행 진행 상태가 있는 계획에서 `9개 슬롯 준비`를 다시 누르면 확인창이 표시되며, 취소하면 기존 계획을 유지합니다. 메인 프로세스도 진행된 계획의 무단 재생성을 차단합니다.

### A안: Windows 작업 스케줄러 자동 실행

현재 구현(회원마당 기반)의 일일 발행 영역에서 `Windows 스케줄러 등록·오늘 놓친 실행 확인` 버튼을 누르면 현재 로그인한 Windows 사용자 계정에 다음 3개 작업이 등록됩니다. 오늘 `morning-prep`(09:00 수집·초안) 성공 기록이 없으면 등록 뒤에 즉시 실행 여부를 묻고, 확인할 때만 `회원마당 수집 → 9개 슬롯 계획 → 초안 생성`을 현재 앱에서 한 번 실행합니다. 오늘 이미 성공한 기록이 있으면 예약 등록만 진행합니다.

| 시각 | 작업 | 동작 |
|---|---|---|
| 09:00 | 회원마당 수집·초안 | 회원마당 수집 → 9개 슬롯 계획 → 초안 생성 |
| 10:30 | 초안 재시도 | 09:00 수집 실패 시 재수집하고, 실패한 초안을 재시도 |
| 10:45~11:45 | 사용자 승인 | 생성된 초안을 확인하고 발행할 항목만 승인 |
| 12:00 | 승인 글 발행 | 11:45까지 승인된 초안만 슬롯 순서·10분 간격으로 발행 |

09:00과 10:30 작업이 끝난 뒤 앱은 사용자가 초안을 확인·승인할 수 있도록 계속 열어 둡니다. 12:00 발행 작업이 끝나면 예약으로 실행된 앱은 종료됩니다. 앱 화면의 `스케줄러 해제` 버튼으로 등록을 취소할 수 있습니다. 등록 상태와 마지막 실행 결과는 `runtime/scheduler-status.json`에서 확인합니다.

컴퓨터가 새벽에 꺼져 있어도 09:00 전까지 다시 켜면 문제가 없습니다. 다만 09:00에도 컴퓨터가 꺼져 있으면 해당 시각에 실행할 수 없습니다. 작업에는 `시작할 수 있을 때 실행(StartWhenAvailable)`이 설정되어 있어 전원이 다시 켜진 뒤 지연 실행을 시도하지만, 이미 지나간 09:00 작업이 정확히 09:00에 실행되는 것은 아닙니다. 절전모드는 `WakeToRun`으로 깨우기를 요청하지만, Windows 전원 정책·하드웨어·노트북 배터리 설정에 따라 깨우기가 차단될 수 있습니다. Chrome 기반 회원마당·네이버 발행 자동화는 사용자가 Windows에 로그인한 대화형 세션에서 가장 안정적입니다.

작업 스케줄러 등록은 앱의 버튼이 자동으로 처리하므로 Windows 작업 스케줄러에서 3개 작업을 직접 만들 필요가 없습니다. 버튼 등록이 권한이나 정책으로 실패할 때만 프로젝트의 `src/lib/register-scheduler.ps1`을 관리자 권한이 필요한지 확인한 뒤 수동 실행하는 대체 방법을 사용합니다.

회원마당 세션이 만료되거나 보안 확인이 필요한 경우, 아이디·비밀번호·CAPTCHA를 자동 입력하지 않습니다. 09:00 수집은 정해진 대기 시간 후 실패로 기록되고, `member-board-source.json`에는 실패 원인과 재시도 가능 상태가 저장됩니다. 10:30에 한 번 수집을 재시도하며, 초안 항목은 항목별로 최대 1회 추가 재시도(총 2회 시도)합니다. 로그인 세션이 끝내 복구되지 않으면 초안을 만들지 않고 12:00 발행도 실행하지 않습니다. 승인된 초안이 하나도 없을 때도 발행하지 않으며, 각 단계의 성공·실패·건너뜀 결과는 `scheduler-status.json`에 남습니다. 09:00 이후 직접 앱에서 로그인·보안 확인을 완료하면 10:30 재시도에서 이어갈 수 있습니다.

### 현재 구현과 요청하신 웹 검색형 기획의 차이

`회원마당`은 특정 원본 사이트입니다. 현재 코드는 `https://onsaecar.co.kr/core/board/member`에 로그인한 뒤 게시글 목록과 본문을 수집합니다. 그 결과를 고정된 9개 출처 분류 슬롯에 배정하고, 각 게시글을 파일 원본처럼 `file_upload` 모드로 Writer Agent에 전달합니다. 이 모드에서는 웹 검색을 실행하지 않습니다.

따라서 현재 일일 흐름은 다음과 같습니다.

1. 회원마당 게시판에서 게시글 수집
2. 게시글을 정부·공공기관·보험·정비·기업·연구·언론·안전·일반 시사 등 9개 고정 슬롯에 분류
3. 회원마당 본문을 사실 근거로 초안 생성
4. 사용자가 초안별 승인
5. 승인된 글만 네이버와 회원마당에 발행. 회원마당 제목에는 `[자동발행]`을 붙이며, 회원마당 게시판에는 카테고리 선택이 없어 제목 표식으로 자동발행 글을 구분합니다.

회원마당 자동 등록은 `https://onsaecar.co.kr/board/add`의 제목 입력칸, 리치텍스트 편집기, 등록 버튼을 사용합니다. 등록 결과와 실패 원인은 일일 계획에 항목별로 저장하며, 수집기는 `[자동발행]`으로 시작하는 제목을 원본 후보에서 제외합니다. 회원마당 로그인·보안확인은 사용자가 열린 Chrome에서 직접 완료해야 합니다.

사용자가 원하신 기획은 다음과 다릅니다.

1. 네이버 블로그 계정에 설정된 9개 카테고리 각각의 키워드와 발행 목적 확인
2. 카테고리별로 최신 웹페이지 검색
3. 검색 결과의 본문·출처를 수집하고 근거 품질 확인
4. 카테고리별 주제와 제목 선정
5. 검색 근거로 초안 생성
6. 사용자 승인 후 발행

기존 일반 작업의 `Research/Title Agent`에는 웹 검색 경로가 있지만, 현재 `회원마당 일일 발행` 스케줄러는 그 경로를 호출하지 않습니다. 결론적으로 현재 구현은 사용자가 말한 웹 검색형 기획과 `정확히 일치하지 않으며`, 회원마당 연동형 별도 기능으로 설계된 상태입니다. 웹 검색형 기획을 기본 일일 자동화로 사용하려면 회원마당 수집 대신 계정별 9개 카테고리를 읽어 카테고리마다 Research/Title Agent와 검색 수집을 실행하는 별도 일일 배치로 교체해야 합니다.

## 검색과 근거 기준

정책, 채용, 지원금, 신청, 모집, 법률, 가격, 일정처럼 독자 행동에 직접 영향을 주는 글은 공식 또는 기관 근거를 우선합니다.

AI 업계동향, 기술 발표, 모델 출시, 반도체 시장 변화 같은 글은 Naver Blog 후보만으로 확정하지 않습니다. 공식 출처가 없더라도 독립 편집 매체 또는 신뢰 가능한 웹 근거가 함께 확인되어야 합니다. 블로그 후보는 주제 발견 단서로 사용할 수 있지만, 블로그만으로 발표형 글을 발행하지 않습니다.

## 실행

```bash
npm install
npm start
```

검사:

```bash
npm run check
npm run check:file-parser
```

빌드:

```bash
npm run dist
```

저장된 작업 실행:

```bash
npm run run:saved
```

최신 생성 결과 발행:

```bash
npm run publish:latest
```

## Tistory 테스트

앱 화면의 `Tistory 테스트 발행` 버튼을 사용하면 Naver 글 생성과 Naver 발행을 건너뛰고 Tistory 로그인, 본문 입력, 이미지 업로드, 카테고리 선택, 태그 입력, 최종 발행 흐름만 빠르게 테스트할 수 있습니다.

## 로컬 데이터와 계정정보

계정 설정, 세션, 브라우저 프로필, 작업 로그, 생성 이미지, 빌드 결과는 Git에 올리지 않습니다. Naver 비밀번호는 앱에 입력하거나 저장하지 않습니다. 대표 제외 대상은 다음과 같습니다.

- `runtime/`
- `dist/`
- `node_modules/`
- `**/user-settings.json`
- `**/account-categories.json`

## 주요 파일

- `src/main.js`: Electron main process, 작업 흐름, 세션 확인, Naver/Tistory 발행 오케스트레이션
- `src/lib/codexRunner.js`: Research/Title, Writer, Main Review, Image Worker 실행과 프롬프트 구성
- `src/lib/search.js`: 검색 후보 수집, 공식/기관/독립 신뢰 근거 판정, source quality 요약
- `src/lib/naverPublisher.js`: Naver 수동 로그인 대기, 글쓰기 편집기, 이미지/카테고리/태그/발행 자동화
- `src/lib/memberBoardCrawler.js`: 회원마당과 기존 Naver 게시글의 Chrome 수집
- `src/lib/dailyWorkflow.js`: 9개 슬롯 분류, 중복 방지, 승인 대기열과 스타일 규칙 저장
- `src/lib/windowsScheduler.js`: Windows 작업 스케줄러 등록·해제·실행 결과 저장
- `src/lib/register-scheduler.ps1`: 일일 09:00/10:30/12:00 작업 등록 스크립트
- `src/lib/tistoryPublisher.js`: Tistory Kakao 세션, TinyMCE 본문 입력, 이미지/카테고리/태그/발행 자동화
- `src/lib/accountStore.js`: 계정과 카테고리 저장 구조
- `src/lib/settings.js`: 앱 설정 기본값과 정규화
- `src/renderer/`: Electron renderer UI
- `scripts/check.js`: 프로젝트 구조와 핵심 회귀 조건 검사
